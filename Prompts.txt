3. Uncertainty-aware (must NOT assume missing data)
4. Resistant to hallucination

STEP 1: INPUT SCHEMA
-----------------------------------

- Age
- Gender
- State
- Rural/Urban
- Annual Income
- Occupation
- Land Ownership (in hectares)
- Land Leasing Status
- Caste Category
- Family Size
- Aadhaar Status (Yes/No)
- Bank Account Status (Yes/No)
- Marital Status

Do NOT add unnecessary fields.

-----------------------------------
STEP 2: RULE REPRESENTATION
-----------------------------------
For each scheme, express eligibility ONLY in strict IF-THEN logic.

Example format:
IF [conditions]
THEN eligible_for_[scheme] = TRUE

Rules must:
- Avoid natural language summaries
- Avoid assumptions
- Mark ambiguity explicitly using:
  ambiguity_flag = TRUE

-----------------------------------
STEP 3: MATCHING ENGINE LOGIC
-----------------------------------
Design the core algorithm that:
1. Takes user input
2. Evaluates all scheme rules
3. Outputs:
   - Fully eligible schemes
   - Conditionally eligible schemes (with missing requirements)
   - Not eligible schemes

Each output must include:
- Rule trace (which rules passed/failed)
- Confidence score (HIGH / MEDIUM / LOW)
- Reason for confidence level

-----------------------------------
STEP 4: AMBIGUITY HANDLING
-----------------------------------
Your system MUST detect and handle ambiguity.

For each scheme evaluation:
- If any rule is unclear, conflicting, or incomplete:
  → Do NOT assume
  → Mark:
     ambiguity_flag = TRUE

Also:
- List ALL possible interpretations
- Reduce confidence score accordingly

-----------------------------------
STEP 5: DEPENDENCY HANDLING
-----------------------------------
Some schemes require prerequisites (e.g., bank account, Aadhaar).

Implement logic such that:
IF prerequisite_missing == TRUE
THEN:
  - Mark scheme as "conditionally eligible"
  - Output required steps to become eligible

-----------------------------------
STEP 6: EDGE CASE RESILIENCE
-----------------------------------
Your system must handle:
- Missing inputs
- Contradictory inputs
- Boundary values (exact cutoffs)

Define how the engine behaves in each case.

-----------------------------------
STEP 7: OUTPUT FORMAT
-----------------------------------
Return output in structured JSON format:

{
  "eligible_schemes": [],
  "conditional_schemes": [
    {
      "scheme": "",
      "missing_requirements": [],
      "confidence": "",
      "explanation": ""
    }
  ],
  "not_eligible_schemes": [],
  "ambiguities_detected": []
}

-----------------------------------
IMPORTANT CONSTRAINTS
-----------------------------------
- Do NOT hallucinate scheme rules
- If scheme data is missing or unclear → explicitly say so
- Prefer “uncertain” over “wrong but confident”
- Do NOT generalize beyond given rules
